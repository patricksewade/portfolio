

DOCUMENT 3 : Stratégie de Routage Front-Controller (Procédural)
## 1. OBJECTIF ET CONCEPTION GLOBALE
Directive pour Antigravity 2.0 : Ce projet ne contient aucun framework. Tu as l'interdiction
formelle de créer des classes orientées objet telles que Router, Request, ou Response.
Le routage de cette application doit être géré par un flux de contrôle procédural pur et
centralisé. L'objectif est de réceptionner toutes les requêtes HTTP dans un point d'entrée
unique, de décoder l'URI et de déclencher l'appel à la fonction métier correspondante.
## 2. LE POINT D'ENTRÉE UNIQUE (FRONT-CONTROLLER)
- Fichier cible : /public/index.php
- Rôle : C'est le seul fichier PHP directement exécuté par le serveur web.
- Comportement attendu par l'agent :
- Initialiser la configuration globale (affichage des erreurs, constantes
## BASE_PATH).
- Démarrer la session (session_start()) après configuration stricte des
cookies (voir Document 5).
- Inclure la connexion à la base de données (PDO).
- Capter la requête courante :
▪ Extraire l'URI : $uri =
parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
▪ Extraire la méthode : $method =
## $_SERVER['REQUEST_METHOD'];
- Appeler la fonction de routage principale : dispatch_request($uri,
## $method, $pdo);
## 3. LA MÉCANIQUE DE ROUTAGE (ROUTER.PHP)
- Fichier cible : /includes/router.php
- Implémentation exigée : Tu utiliseras la puissance procédurale de PHP 8.x,
notamment l'expression match ou un bloc switch/case structuré, pour associer
chaque couple (URI + Méthode) à une fonction contrôleur spécifique.
- Exemple de flux attendu :
o Si $uri === '/' et $method === 'GET' ➔ Appeler
handle_home_page($pdo)
o Si $uri === '/contact' et $method === 'GET' ➔ Appeler
handle_contact_page()
o Si $uri === '/contact' et $method === 'POST' ➔ Appeler
handle_contact_post($pdo)
o Si $uri === '/admin/dashboard' ➔ Appeler
handle_admin_dashboard($pdo)
## 4. LES FONCTIONS CONTRÔLEURS (ACTION DISPATCHING)
- Localisation : Fichiers dans /includes/controllers/ (ex:
home_controller.php, contact_controller.php).
- Responsabilités strictes de chaque fonction contrôleur :

- Sécurité : Vérifier les autorisations (ex: vérifier la session admin si route
protégée).
- Validation : Assainir et valider les données entrantes ($_GET, $_POST).
- Action (DAL) : Appeler les fonctions de la base de données (ex: $projects
= get_all_projects($pdo);).
- Vue : Charger le gabarit HTML final en passant les variables via l'inclusion
du template.
- Alerte Rouge : Les fonctions contrôleurs ne doivent JAMAIS contenir de requêtes
SQL brutes ($pdo->query(...)) ni de code HTML directement écrit via echo.
## 5. GESTION DES ERREURS HTTP (FALLBACKS)
L'agent devra implémenter une gestion rigoureuse des routes introuvables ou des méthodes
non autorisées.
- Erreur 404 (Not Found) : Si la variable $uri ne correspond à aucune route définie,
la fonction dispatch_request() doit explicitement appeler
http_response_code(404); et inclure la vue templates/pages/404.php.
- Erreur 405 (Method Not Allowed) : Si l'URI existe mais que la méthode HTTP est
incorrecte (ex: appel GET sur le traitement du formulaire de contact), le code
http_response_code(405); doit être émis.
