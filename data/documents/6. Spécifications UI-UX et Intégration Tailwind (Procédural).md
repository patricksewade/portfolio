

DOCUMENT 6 : Spécifications UI/UX et Intégration Tailwind
(Procédural)
## 1. OBJECTIF ET CONTRAINTES DE TEMPLATING
Directive pour Antigravity 2.0 : Ce projet exclut totalement l'utilisation de moteurs de
templating externes (pas de Twig, pas de Blade, pas de Smarty). PHP natif sera utilisé comme
moteur de vue.
- Alerte Rouge : L'agent a l'interdiction formelle de créer des classes de type View,
TemplateEngine ou Component. La réutilisation du code HTML se fera
exclusivement par l'inclusion de fichiers partagés (require) et par l'appel de
fonctions d'affichage (composants procéduraux).
- Séparation stricte : Les fichiers du dossier /templates ne doivent contenir aucune
logique métier complexe ni requêtes PDO. Ils reçoivent des variables préparées par le
contrôleur et se contentent de les afficher.
## 2. LE GABARIT PRINCIPAL (MASTER LAYOUT)
Sans mécanisme d'héritage objet, l'encadrement des pages se fera de manière procédurale :
- Fichiers structurels : L'agent devra créer /templates/layout/header.php
(contenant le <head>, l'intégration de Tailwind, et la barre de navigation) et
/templates/layout/footer.php (contenant le pied de page et la balise
## </body>).
- Mécanisme d'assemblage : Chaque vue de page (ex: home.php) devra respecter la
structure suivante :
- Définition des variables dynamiques du header (ex: $page_title =
"Portfolio | Ernest Patrick SEWADE";).
- Appel de require BASE_PATH .
## '/templates/layout/header.php';.
- Contenu spécifique de la page (HTML).
- Appel de require BASE_PATH .
## '/templates/layout/footer.php';.
## 3. LES COMPOSANTS UI PROCÉDURAUX (SIMULATION DE REACT/BLADE)
Pour éviter la duplication massive de balises HTML et de classes Tailwind, l'agent devra
isoler les éléments réutilisables.
- Localisation : Création d'un dossier /templates/components/.
- Stratégie : Au lieu d'inclure de petits fichiers HTML, l'agent codera des fonctions
PHP qui génèrent et retournent (ou affichent) le HTML.
o Exemple attendu : Une fonction render_project_card(array
$project_data) qui encapsule toute la structure HTML d'une carte de
projet et utilise la fonction e() pour sécuriser les données affichées.
o Exemple attendu : Une fonction render_button(string $label,
string $url, string $style_classes).

## 4. DIRECTIVES TAILWIND CSS ET DESIGN SYSTEM
- Intégration MVP : Pour garantir une mise en production ultra-rapide, Tailwind CSS
sera chargé via le CDN officiel dans la balise <head> du header.php. L'agent ne
doit pas configurer de pipeline de build Node.js (pas de npm, pas de webpack) pour
cette V1.
- Interdiction de CSS personnalisé : L'agent a l'interdiction de créer des fichiers
.css avec des règles métier. L'approche est 100% "Utility-First".
- Charte Graphique "Light / Minimalist" (Instructions strictes pour l'UI) :
o Thème : Conception claire, lumineuse, professionnelle. Pas de thème sombre
(Dark Mode) pour la V1 afin de limiter la charge de code.
o Couleurs : Fond de page blanc ou très clair (bg-white, bg-slate-50).
Texte principal à fort contraste (text-slate-900 ou text-slate-800).
Utilisation d'une couleur d'accentuation sobre pour les boutons et les liens (ex:
text-blue-600, bg-slate-900).
o Typographie : Importation de la police "Inter" ou "Roboto" via Google Fonts.
Privilégier une hiérarchie visuelle claire (ex: text-4xl font-extrabold
tracking-tight pour les titres principaux).
o Whitespace : Utilisation généreuse des marges et paddings (ex: py-16, gap-
8) pour donner un aspect aéré et organisé.
## 5. SYNTAXE ALTERNATIVE ET GESTION DES ASSETS
- Syntaxe de contrôle (Lisibilité) : Dans tous les fichiers de vue, l'agent a l'obligation
d'utiliser la syntaxe alternative de PHP pour les structures de contrôle (interdiction des
accolades { } dans le HTML).
o Exigé : <?php foreach ($projects as $project): ?> ...
<?php endforeach; ?>
o Exigé : <?php if ($condition): ?> ... <?php endif; ?>
- Chemins absolus front-end : Pour garantir le bon affichage des images et des assets,
l'agent devra définir et utiliser une constante URL globale (ex: BASE_URL) pour
préfixer toutes les balises <img src="..."> et <link href="...">.
- Rappel de sécurité final : Absolument chaque variable affichée dans ces templates
($project['title'], $message, etc.) doit être encapsulée dans la fonction
d'échappement procédurale e().
