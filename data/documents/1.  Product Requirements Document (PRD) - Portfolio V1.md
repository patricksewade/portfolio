Cible : Recruteurs techniques (CTO, Lead Devs) en France pour l'obtention immédiate d'un

## CDI.

Urgence de livraison : Critique. Le projet doit être déployé et fonctionnel dans les plus brefs
délais pour permettre un changement de statut administratif (avant l'échéance de novembre
2026). Le périmètre doit donc être traité comme un Produit Minimum Viable (MVP)
intransigeant sur la qualité, mais restreint sur la quantité de fonctionnalités.

## 2. DIRECTIVES FONDAMENTALES POUR L'AGENT "ANTIGRAVITY 2.0"

Antigravity 2.0, tu agiras en tant qu'exécutant technique sous ma supervision architecturale.
Tes instructions système pour ce projet sont les suivantes :

- Paradigme imposé : PHP 8.x (8.4/8.5) STRICTEMENT PROCÉDURAL.
- Interdictions absolues (Alerte Rouge) :
  o AUCUNE Programmation Orientée Objet. Interdiction formelle d'utiliser les
  mots-clés class, interface, trait, extends, implements, new (à
  l'unique exception de l'instanciation de PDO).
  o AUCUN framework (ni Symfony, ni Laravel, ni micro-framework).
  o AUCUN ORM (ni Doctrine, ni Eloquent).
  o AUCUNE librairie externe nécessitant Composer pour la logique métier ou
  l'envoi d'emails (pas de PHPMailer, pas de SwiftMailer).
- Standard de qualité : Déclaration declare(strict_types=1); obligatoire en
  tête de chaque fichier PHP. Typage strict des paramètres et des retours de toutes les
  fonctions.

## 3. PÉRIMÈTRE FONCTIONNEL (MVP)

3.1. Front-Office (Espace Public)

- Page d'Accueil : Présentation courte et percutante du profil (Master 2, focus
  backend/full-stack) et mise en avant des compétences clés.
- Section Portfolio (Projets) : Affichage dynamique des projets récupérés depuis la
  base de données.
  o Mise en exergue obligatoire : Le projet "KLG-Caisse" (migration d'un
  logiciel de caisse vers une architecture moderne) doit bénéficier d'un
  traitement visuel prioritaire ou d'une section dédiée pour démontrer la capacité
  à gérer des logiques métier complexes.
- Page de Contact : Formulaire de contact sécurisé (Nom, Email, Sujet, Message).
  3.2. Fonctionnalité de Contact : Protocole SMTP Natif (Directive Agent)

- L'envoi d'emails via ce formulaire ne doit pas utiliser la fonction mail() basique
  (trop incertaine) ni une librairie POO.
- Implémentation requise : L'agent devra coder une fonction procédurale
  communiquant directement avec un serveur SMTP (Google Workspace, SendGrid ou
  autre) via l'utilisation stricte de sockets natifs PHP (stream_socket_client ou
  fsockopen).
- Cette fonction devra gérer manuellement le dialogue SMTP (EHLO, AUTH LOGIN,
  MAIL FROM, RCPT TO, DATA, QUIT) et l'encodage en Base64 des identifiants.
  3.3. Back-Office (Administration Minimaliste)
- Page de Connexion : Authentification par mot de passe haché (un seul compte
  administrateur en base de données).
- Dashboard d'administration :
  o Lecture des messages reçus via le formulaire de contact.
  o Opérations CRUD rudimentaires sur la table des projets (pour modifier les
  liens ou la description de KLG-Caisse par exemple).

## 4. SPÉCIFICATIONS UI/UX ET INTÉGRATION

Thème et Direction Artistique : Light & Minimalist.
L'objectif est de projeter l'image d'un développeur organisé et rigoureux.

- Identité visuelle : Beaucoup d'espaces blancs (whitespace), design aéré, typographie
  hautement lisible (sans-serif type Inter ou Roboto). Contraste élevé (texte sombre sur
  fond très clair).
- Technologie UI : Utilisation exclusive de Tailwind CSS (chargé via CDN pour la

## V1).

- Directives d'intégration pour l'Agent :
  o Interdiction d'écrire des fichiers .css personnalisés avec des règles métier.
  Tout le design doit se faire via les classes utilitaires de Tailwind.
  o Pour éviter la duplication de classes (puisqu'il n'y a pas de composants
  Twig/Blade), l'agent devra créer des fonctions PHP d'affichage (ex:
  render_button(string $label, string $url)) qui encapsulent
  les longues chaînes de classes Tailwind.
